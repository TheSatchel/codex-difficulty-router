主对话保持当前模型，负责理解需求、分类、分配、验收和汇总；执行优先交给原生 subagent。委派不扩大任务、权限或预算授权。已被委派的子代理只执行指定任务，不递归调度。

## 先分类，再按规则选择

没有具体任务时，说明“已检查路由，等待具体题目，尚未派发”，不空派子代理、不提前查榜。实质任务开始时读取[输入、输出和验收契约](references/routing-contract.md)：

1. 主模型只把任务标成 transform、bounded-edit、investigate 或 design，并明确验收条件与稳定的 profile；不再估计数字能力下限，不声称某任务需要某个 Intelligence Index。未知或混合任务按 design 处理，续做保留类别直到范围实质改变。
2. 不要求模型凭自我认知说出当前型号。先运行 node <SKILL.md所在目录>/../../bin/router-data.mjs context，读取当前 CODEX_THREAD_ID 对应的活动回合记录，取得真实模型／推理档。它只输出模式元数据，不读取其他聊天内容或全局默认模型；实际速度未记录就保留未知。
3. 从宿主原生工具目录取得实际可用模型及档位，构造契约请求 JSON，运行 node <SKILL.md所在目录>/../../bin/router-data.mjs route --request <请求JSON路径> --current。占位符须替换成真实路径。--current 会直接填入本轮实际 parent，覆盖请求中可能过期的 parent；请求可以不写 parent。速度继承仍须由宿主明确支持，不能编造独立速度参数。

工具默认尝试公开榜单，失败时回退仍有效的完整内置快照；--offline 只查快照。没有验收记录就传空 evidence，决策器会按任务规则分配。模式读取失败时报告具体 reason，不再说“无法决策，所以直接继承主模式”。没有日志的临时／远程宿主可用其明确暴露的实际模式填 parent，不能猜默认配置。

## 解释并执行结果

- task-policy-route：没有足够可比较的任务记录时，按任务类型明确分配：transform 低档／经济型，bounded-edit 中档／均衡型，investigate 高档／强能力型，design Max／强能力型。型号从实际可用且满足上限的候选中选择，不是固定硬编码型号。这是启发式分配，不冒充验收通过或已证明省钱。
- evidence-route：根据同类别、同 profile、同速度的真实成对验收记录选择模型。把返回的精确 model／effort 用于宿主原生创建接口，不再按个人感觉改选另一档；速度继续继承。
- blocked：没有可用的实测或有据推断参考、身份不明确、数据过期或速度继承无法确认，不能派发。精确档位缺分本身不再阻塞；例如 Ultra 可以使用同型号 Max 的近似参考，但不得声称 Ultra 已有实测。

评分返回 usableForRouting 为 true 时可继续，包括 status 为 estimated 的情况；verified 只代表精确实测。推断采用同完整型号、同指数版本的锚点：有上下实测档位时插值，否则使用模型级分数或最近实测档位，超出实测范围不随意加分。公开估计值保持估计标签。完全没有数值来源时才保留未知，不跨版本、跨型号猜分。

如果主模式或选中子模式用了估计，简短说明近似值和依据，如“Ultra 暂参考同型号 Max 约 56.9”；不要再因没有 Ultra 单独测分就报告无法路由。指数上限按这些参考值比较，不能证明真实能力的严格大小；实际推理档和速度仍不得超过主模式。严格实测模式仅在用户明确要求时使用 --strict 或 allowEstimates: false。

每次创建子代理都显式传入返回的 model 和 reasoning_effort，不省略参数来继承主档位；即使选中模式恰好等于主模式，也必须是任务分配的结果。候选为空或任务档位内无法分配时明确受阻。主模式只限定上限，任务目标档位会被主上限截断；速度仍按宿主继承。

榜单用于准入、上限及初始模型档次的相对排序，不能证明任务能力。已有足够可比记录时优先采用 evidence-route；默认至少 3 个成对任务、最近 30 天无能力失败，才声称记录支持优化。无记录仍执行任务分配，不等待凑齐样本。规则公开于 [routing-policy.json](../../data/routing-policy.json)。

有成对证据时，normal 优先费用更低，urgent 优先费用不增加且耗时更低。初始规则缺少可靠费用／耗时时不宣称成本优化，但仍按任务分配。费用、耗时包含全部重试与协调开销；USD 和 credits 不混用。用户预算仍须在派发前核对，历史均值不能当成当前任务费用保证。

首次检查、模式变化或阻塞时，简短报告实际主模式、任务类别和结果理由。状态不变时不重复播报，不把未读取数据说成没有评分。单纯查询评分仍可使用 assess --model <实际ID> --effort <实际档位>；verified 只表示评分已核实，不等于任务已验证。

## 验收与记录

子任务明确输入、交付物、验收和写入范围；独立工作并行，冲突写入串行。主对话检查真实交付物和必要验证，区分创建成功、任务完成与验收通过，随后关闭完成的代理。极短问答、强耦合决策和紧急阻塞可以留在主对话。

只在用户指定的任务文件中保存实际已发生的执行记录，记录格式见契约；没有指定记录位置时用本任务临时文件，不建立全局数据库、不扫描其他聊天。不为了凑样本自动重跑付费任务，不测试未准入模型，不把本插件元数据测试或模拟演练当成模型能力证据。没有可靠记录时保持 evidence 为空。

能力失败会暂停该候选在相应 profile 的优化资格；环境、权限、工具或依赖失败单独记录，不能据此升模型。重试前先判断失败原因及预算；需要改派时重新执行路由，始终不超过主模式，不自动提高主模型。未经解决的失败保留未完成状态。

## 宿主和加载边界

需要默认加载时使用个人指令中的[入口规则](../../prompts/codex-entry.md)。它只在本技能位于当前可用列表时生效，禁用或卸载后不寻找旧副本。Skill 是文字指导，数据工具只计算决策，均不控制当前聊天模型或创建后台执行器。

决策器当前使用 Codex 的推理档顺序。Claude Code 可以遵循准入、证据和验收原则，但不得套用未验证的 Codex 档位映射；宿主能力不足时明确说明。普通持久化聊天不作为自动拆分目标，不向其他聊天发送隐藏消息。

完整公开榜单位于 [leaderboard.json](../../data/leaderboard.json)；查询不写文件。需要另存公开缓存时才用 cache --cache-dir <明确目录>，不重建用户已清理的全局目录。禁止为路由安装 LaunchAgent、daemon、MCP、用户 hook，修改 CODEX_*、App 文件、全局运行配置或 app-server 连接，禁止历史桌面安装器。
